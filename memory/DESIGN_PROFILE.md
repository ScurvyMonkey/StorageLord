# Design Profile

How this designer communicates, what they value, how they make decisions — logged by `/ba`.

### [2026-09-15] — BA — Genre references describe the goal, not a literal mechanic to copy; converges fast on Recommended when forks are flagged clearly
**Context:** First real spec pass (#1, Runtime Grid Placement). The ask cited "stacking in Satisfactory" as the reference for wanting height/verticality in the grid.
**Learning:** Read literally, Satisfactory's verticality comes from foundation-based multi-story building (support required below), not freeform floating placement. Rather than assume the literal mechanic, surfaced it as an explicit fork (freeform vs. requires-support-below) via a 2-question `AskUserQuestion` batch alongside a second real fork (whether to also extend the Editor-time platform tool). Both answered with the Recommended option in one pass, no deliberation — the Satisfactory mention was about the *outcome* they want (compact vertical storage, not flat sprawl), not a request to build support/foundation logic.
**Apply when:** When a request cites another game as a reference point, treat it as describing the feeling/outcome they want, not a spec for that game's literal systems — if the literal mechanic would meaningfully change scope or architecture, surface it as an explicit question rather than assuming either the literal or the simplified reading. This designer converges quickly on a clearly-labeled Recommended option once the fork is visible, even across multiple bundled questions.

### [2026-09-14] — BA — Multiple cited games can itself be the ambiguity; picks the option matching existing project signals over the genre default
**Context:** Camera system ask (#2) cited "Shapez or Shapez 2" together, as if interchangeable. They aren't — Shapez 1 is locked top-down orthographic, Shapez 2 is free-orbit perspective. Also relevant: GDD's own Open Questions note said genre precedent points toward top-down/isometric, which would have argued for the "simpler" reading.
**Learning:** When a request names two+ games as one reference, don't assume they're equivalent — check whether they actually differ on the axis that matters and surface that as the fork. This designer picked the option that matched an existing but easy-to-miss project signal (`CLAUDE.md`'s Unity MCP note that this is "a 3D project, not 2D top-down like other projects") over the GDD's own stated genre-precedent lean toward top-down/isometric — i.e., they weight concrete project-specific signals over general genre-default reasoning.
**Apply when:** A request cites multiple games/references together — verify they actually agree before treating them as one reading. When surfacing the fork, check `CLAUDE.md`/GDD for any existing signal (even an offhand one) that already leans toward an answer, and don't let a stated "genre precedent" note override a more specific project signal when framing the Recommended option.

### [2026-09-15] — BA — Will reverse an earlier "Recommended, agreed" decision once they've actually played it; doesn't default to Recommended when a bundled action changes what a single click does
**Context:** #1's fork picked "freeform" placement (the Recommended option at the time) over "requires support below." After playing the freeform version and hitting an unrelated placement bug, the designer came back unprompted and asked for support-required auto-stacking — the exact mechanic freeform had been chosen over. Separately, in that same follow-up spec (#3), a 3-option fork asked what happens removing a container with something stacked on top: they picked "cascade-remove the whole stack" over the Recommended "block the removal," while still picking Recommended on the other two forks in the same spec (support-detection method, stack cap).
**Learning:** A "Recommended, agreed" choice from an earlier spec is not a settled preference — it's provisional until played. Don't treat prior spec decisions as closed; if the user reopens one, that's them acting on real play experience, not indecision, and it deserves the same full fork treatment as a first-time ask. Also: this designer doesn't rubber-stamp Recommended across a bundled question set — they pick per-question based on what feels right for that specific interaction, and readily go with the *more permissive/less restrictive* option (cascade-remove, a bigger single action) over the *safer/more conservative* one (block removal) when the safer option would make a common interaction (clearing a stack) more tedious.
**Apply when:** Never assume an old spec decision is final just because it was agreed to and shipped — if the user's later request would functionally reverse it, treat it as a real re-fork, not a bug report. When a bundled `AskUserQuestion` includes both a "safe/blocking" and a "permissive/bulk-action" option, don't assume Recommended (often the safe one) is the likely pick — this designer weighs player convenience for common actions over defensive restriction.
